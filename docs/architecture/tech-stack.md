# Tech stack

TypeScript end to end, PostgreSQL for storage, Docker for everything: development, tests, CI and deployment. Each choice links to the decision record that explains it.

| Layer | Choice | Why | Alternatives considered | Decision |
| --- | --- | --- | --- | --- |
| Language | TypeScript | One language for API and UI; shared types | Python, Go | [ADR-0004](decisions/0004-typescript-fastify-drizzle-react.md) |
| Runtime | Node.js (current LTS) | Mature, runs well in a small container | Deno, Bun | [ADR-0004](decisions/0004-typescript-fastify-drizzle-react.md) |
| Repository | Monorepo: `apps/api`, `apps/web`, `packages/shared` | Shared types and date parser without publishing | Separate repos | [ADR-0006](decisions/0006-monorepo-with-docker-only-development.md) |
| Package manager | pnpm workspaces, via corepack inside containers | Fast, strict dependencies, good monorepo support | npm | [ADR-0006](decisions/0006-monorepo-with-docker-only-development.md) |
| Development environment | Docker Compose only, driven by `make` | Machine-agnostic; host needs Docker and make only | Host-installed Node.js | [ADR-0006](decisions/0006-monorepo-with-docker-only-development.md) |
| Web framework | Fastify | Lightweight, schema-based validation, good TypeScript support | NestJS, Express | [ADR-0004](decisions/0004-typescript-fastify-drizzle-react.md) |
| API style | REST, TypeBox schemas, generated OpenAPI | One schema for validation, types and docs; any client can use it | tRPC, GraphQL | [ADR-0007](decisions/0007-rest-api-with-typebox-schemas.md) |

| IDs | UUIDv7, generated by the app | Time-ordered: compact indexes, natural creation order | UUIDv4 | [Data model](data-model.md) |
| Sign-in | OAuth only: Google first | No passwords to store or leak | Username and password | [ADR-0008](decisions/0008-oauth-only-sign-in.md) |

## Quality gates

Every pull request runs, through the same `make` targets used locally:

| Gate | Tool |
| --- | --- |
| Formatting | Prettier |
| Lint | ESLint |
| Types | `tsc --noEmit` across all workspaces |
| Unit tests | Vitest |
| Database and repository tests | Vitest against the `db-test` PostgreSQL 16 container |
| Visibility tests | Per-role, per-endpoint field assertions ([ADR-0009](decisions/0009-per-tree-roles-and-protected-view.md)) |
| End-to-end tests | Playwright, against the built image |
| Dependency audit | `pnpm audit` (high and critical) |

`main` is protected: changes land through pull requests with all gates passing.

The repository and visibility tests use a fixed, invented sample family that includes remarriage, half-siblings, adoption and a cousin marriage.

## Resource budget

The NAS shares its memory with other apps. The Nôs Raiz container should stay under roughly 200 MB at idle. PostgreSQL is the existing shared instance, so it adds only a database, not a server.
