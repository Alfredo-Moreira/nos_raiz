# Nôs Raiz

Genealogy platform for Cape Verde and its diaspora. Pre-MVP: design is documented, no application code yet. Start at [docs/README.md](docs/README.md).

## Where things live

These locations override the defaults in any skill (for example `domain-modeling` expects a root `GLOSSARY.md` and `docs/adr/`):

| What | Where | Format |
| --- | --- | --- |
| Glossary (domain terms) | [docs/glossary.md](docs/glossary.md) | Table: term, meaning. No implementation details |
| Architecture decisions | [docs/architecture/decisions/](docs/architecture/decisions/README.md) | MADR, from `template.md`; next free number; add to the index |
| Data model | [docs/architecture/data-model.md](docs/architecture/data-model.md) | Provisional until the nodes design session |
| Open questions | [docs/README.md](docs/README.md#open-questions) | Table |

Accepted ADRs are never rewritten in substance; a changed decision gets a new ADR that supersedes the old one.

## Non-negotiables

- **No real family data** in the repo, tests, fixtures or screenshots. Invented sample data only.
- **Protected view by default** ([ADR-0009](docs/architecture/decisions/0009-per-tree-roles-and-protected-view.md)): viewers and link visitors never receive full dates, sub-country places or notes. Enforced in the API's visibility filter, covered by per-role tests.
- **OAuth only** ([ADR-0008](docs/architecture/decisions/0008-oauth-only-sign-in.md)): never add password storage.
- **Docker only** ([ADR-0006](docs/architecture/decisions/0006-monorepo-with-docker-only-development.md)): every command runs through `make` and `docker compose`; nothing assumes tools installed on the host.
- **PostgreSQL 16** (matches the NAS). Check version-specific features against 16, not newer.
- **UUIDv7** IDs generated by the app.
- All graph traversals go through the `GenealogyRepository`; nothing else writes recursive queries.

## Workflow

- Branch per change (`feat/…`, `fix/…`, `docs/…`, `chore/…`); Conventional Commits; PRs into `main`.
- Update the relevant doc in the same PR as the change.
